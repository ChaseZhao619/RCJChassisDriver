# BSP 硬件驱动与调参手册

`Bsp` 是 Board Support Package，负责把具体硬件细节封装成稳定接口，供 `App` 层调用。简单说，`App` 层关心“让底盘移动”，`Bsp` 层负责“怎么驱动 CAN 电机、读 IMU、发 PWM、读 GPIO”。

本文档说明 `Bsp/Inc` 与 `Bsp/Src` 中各模块的职责、坐标约定、可调参数和建议调试流程。所有电流值均为大疆 C610/C620 协议中的控制量，并非毫安；实际电流换算应以所用电调手册为准。

## 安全与免责声明

> 危险：BSP 层直接访问电机、PWM、GPIO、I2C 和 CAN。错误的方向宏、引脚配置、PWM 脉宽、电流上限或 PID 参数可能导致执行器突然动作、堵转、过热或机械损坏。

所有 BSP 测试都应先在低功率、架空或隔离负载条件下执行。本项目不保证默认参数适用于所有硬件版本，使用者需要自行验证并承担风险。

## 贡献与维护说明

> 重要：BSP 改动通常和具体硬件强相关。参数类改动不应只提交“调好了”的结果，应说明调参依据和观察到的现象，方便后续换车或维修时追溯。

提交前建议记录：

- 测试所用电机、电调、传感器、供电电压和机械结构。
- 修改的方向宏、PID、阈值或引脚。
- 测试是在架空、落地、低速还是比赛场地完成。
- 是否影响 `App` 层命令语义或上位机行为。
- 是否需要更新原理图、接线表、`.ioc` 或固件主 README。

维护规则：

- 新增 BSP 模块时，至少提供 `Init`、核心操作接口、关键参数宏和错误/状态返回说明。
- 修改硬件引脚时，同步更新 `.ioc`、CubeMX 生成代码、固件主 README 和本手册。
- 修改控制参数默认值时，在注释或本文档中说明影响和调参建议。
- 新增测试宏时，默认值必须为关闭状态。

## 你应该先知道

- 方向错误不能靠 PID 修正，必须先改方向宏。
- 同一时间只启用一个 `*_TEST_ENABLE`。
- 先调轮速环，再调角度环，最后调里程计和 App 层运动参数。
- 传感器阈值、PID、电流上限都和实车状态有关，不能直接照搬到另一台车。
- 每次只改一组参数，并记录现象，否则很难判断效果来源。

## 调参前检查表

> 注意：只要底盘可能运动，就必须架空底盘或确保场地安全。

- [ ] 底盘已架空，轮子不会碰到地面或人员。
- [ ] 独立急停可用，`cmd_conmotion 0` 能立即停止运动输出。
- [ ] 只开启一个测试宏，例如只开启一个 `*_TEST_ENABLE`。
- [ ] CAN 电机 ID、供电、终端电阻正常。
- [ ] 先确认电机旋转方向和反馈方向，再开始调 PID。
- [ ] 首次测试使用较小 `MAX_CURRENT` 和速度上限。
- [ ] 测试前确认吸力电机、踢球电机、继电器外接负载安全。

## 坐标系与正方向

- 底盘平移：`forward` 为车体前方，`left` 为车体左方。
- 极坐标方向：`0 deg` 为前方，`90 deg` 为左方，角度按逆时针增加。
- 旋转：`ccw` 为从上向下看逆时针。
- 里程计世界坐标：`x`、`y` 由车体速度结合当前偏航角积分得到。
- 若某轴运动方向、编码器反馈或陀螺仪符号不符，优先修改对应 `*_DIR`。

## PID 小白版解释

- `KP`：反应速度。增大后更快追目标，过大会抖动或振荡。
- `KI`：消除长期误差。增大后更容易消除稳态误差，过大会积累过多输出。
- `KD`：抑制过冲。能让系统更稳，但会放大速度或传感器噪声。
- `KF`：前馈。根据目标先给一个基础输出，减轻 PID 追赶压力。
- `I_LIMIT`：积分上限。限制 `KI` 累积，避免停下后输出长时间不回零。
- `MAX_CURRENT`：输出上限。保护电机、电调和机械结构。

## 推荐调参顺序

### 1. 电机与方向

使用 `bsp_motor_test` 的小电流逐个确认 CAN ID 1~5。确认底盘四个轮子的 `BSP_CHASSIS_MOTORx_DIR` 后，再确认 `BSP_CHASSIS_MOTORx_FB_DIR` 能使“正目标速度对应正反馈速度”。功能电机同理检查 `BSP_KICK_MOTOR_DIR` 与 `BSP_KICK_MOTOR_FB_DIR`。

常见问题：

- 车不按预期方向动：先查电机编号和方向宏。
- 目标速度为正但反馈为负：查反馈方向宏。
- 某个电机没有反馈：查 CAN ID、接线、供电和反馈超时。

### 2. 底盘轮速环

暂时关闭角度保持并架空底盘：

1. 将 `KI`、`KD` 置零，`KF` 从较小值开始，使中高转速下的基础输出接近目标。
2. 增大 `KP`，直到跟随足够快且尚未出现持续振荡。
3. 缓慢增加 `KI` 消除稳态误差。
4. 只有确认噪声可控且确有超调需求时才增加 `KD`。
5. 最后在负载和低电量条件下复测 `MAX_CURRENT`、温升和堵转保护。

常见问题：

- 高频抖动：`KP` 或 `KD` 可能过大，也可能反馈噪声过大。
- 启停后输出长时间不回零：减小 `KI` 或 `I_LIMIT`。
- 低速不动：检查静摩擦、`KF`、最小输出和电流上限。

### 3. 偏航角保持

先确认 `BSP_CHASSIS_GYRO_Z_DIR` 和 `BSP_CHASSIS_YAW_CTRL_DIR`：人为逆时针转动车体时，逻辑角速度及控制输出应符合正方向。

1. 从较小 `ANGLE_KP` 开始，提高到回正速度满足要求。
2. 若接近目标仍来回摆动，增大 `ANGLE_GYRO_KD`；若响应迟钝或无法快速回正，适当减小。
3. 静止抖动先检查 IMU 噪声，再调整 `GYRO_DEADBAND_DPS` 和 `ANGLE_DEADBAND_DEG`。
4. 小误差克服不了静摩擦时提高 `ANGLE_MIN_RPM`；过高会造成目标附近极限环。
5. 用 `ANGLE_MAX_RPM` 和 `ANGLE_MAX_CURRENT` 设置最终安全上限。

常见问题：

- 车头越修越偏：检查 yaw 控制方向。
- 静止也抖：检查 IMU 噪声、死区和最小转速。
- 回正很慢：检查 `ANGLE_KP`、最大转速和最大电流。

### 4. 运动耦合补偿

将车头锁定，在平整场地分别执行纯前进和纯左移。纯前进发生稳定横漂时调整 `FORWARD_TO_LEFT_COMP`；纯左移发生稳定纵漂时调整 `LEFT_TO_FORWARD_COMP`。

该补偿只修正近似线性、可重复的机械耦合，不能代替轮速环，也不能解决轮胎打滑。

### 5. 里程计比例

先准确测量轮径和减速比，再进行长直线标定：

- `实际距离 / 里程计距离` 可作为当前方向比例系数的乘法修正量。
- 前后方向修正 `BSP_CHASSIS_ODOM_FORWARD_SCALE`，左右方向修正 `BSP_CHASSIS_ODOM_LEFT_SCALE`。
- 至少双向各测多次并取平均，避免地面坡度、轮胎打滑和偏航误差影响结果。
- 比例正确后再调 `POS_KP`、最小速度、最大速度和到点容差。

## 传感器与执行器调试

### BE1732 红外复眼

`NO_BALL_VALUE_THRESHOLD` 是最强通道值低于或等于多少时视作一次“无球”；`NO_BALL_COUNT_LIMIT` 是连续多少次无球后才输出无球。

```text
无球确认时间 = 调用 BspBe1732_ReadFilteredChannel() 的周期 × NO_BALL_COUNT_LIMIT
```

阈值应采集“无球环境噪声”和“最远有效球信号”后选在两者之间。更高阈值更容易判无球；更大的计数限制更稳定，但丢球响应更慢。阈值写入 Flash，频繁写入会消耗擦写寿命。

### BNO085

报告周期 `interval_us` 越短，姿态更新越快，但 I2C 占用和 MCU 解析负载越高。主循环必须足够频繁读取，否则传感器缓冲区可能积压。先用较慢周期确认通信稳定，再按控制带宽缩短。

### 吸球检测

`BSP_SUCTION_DETECT_ACTIVE_LEVEL` 只配置逻辑极性。若传感器输出会抖动，应在任务层按固定周期连续采样并做计数消抖，不能通过 GPIO 上拉/下拉替代时间滤波。

### PWM 吸力电机

`BspSuctionMotor_Init()` 使用初始化脉宽使 ESC 进入可接受状态。只有完成电调说明书要求的上电/解锁流程后才能提高脉宽。首次测试应拆除负载或采取防护，从低脉宽逐级增加并观察电流、温升和机械振动。

## 测试代码使用原则

- `bsp_motor_test`：低电流逐个验证 CAN 电机和方向。
- `bsp_chassis_test`：验证四轮合成运动及偏航保持。
- `bsp_chassis_angle_test`：专用于角度环，落地前先架空确认控制方向。
- `bsp_chassis_odom_calib_test`：用于固定距离的前后/左右比例标定。
- `bsp_chassis_odom_test`：按场地边界运行，必须先确认场地尺寸、车体尺寸和急停手段。
- `bsp_suction_motor_test`：逐级改变 PWM，测试时限制最大脉宽。

测试宏为 `1U` 时可能在上电后自动驱动执行器。烧录前应检查所有测试头文件，并确认只有预期测试处于启用状态。
